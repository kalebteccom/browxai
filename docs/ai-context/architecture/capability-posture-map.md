# Capability posture map

Safe by default, with no auto-broadening. The gate returns a structured capability-required refusal (`requiredCapability` names the missing capability), never a silent no-op. `test/keystone/capability-denials.keystone.test.ts` asserts the refusal against a default-set server for `captcha`, `credentials`, `secrets`, `network-body`, `extensions`, `canvas`, `file-io` (the 13 tool-gated tools plus `screenshot({path})`), `diagnostics`, `eval` (`poll_eval` and the document and script branches of `route`, `route_queue` and `sw_intercept_fetch`), the `network-body` arms of `open_session({har})` and `caches_get`, `action` for `open_session` `storageState` / `authState` / `hars` and for `profile_restore` on a server without it, `secrets` for `get_credential` with `credentials` on, and, as behaviour branches, `clipboard` and `stealth`. The other capabilities are pinned by their own feature keystones or unit tests; check before assuming a capability has a denial keystone.

## Default-on capabilities

These are enabled. Withholding them reduces browxai to a read-only crawler.

| Capability   | Tools                                                                                        | Rationale                                                                                                                |
| ------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `read`       | snapshot, find, text_search, inspect, console_read, network_read (metadata only), screenshot | Observation has no side effect on the page; safe to enable everywhere.                                                   |
| `navigation` | navigate, go_back, go_forward, scroll, set_viewport                                          | URL changes are visible to the agent and to the user. `navigate` opens web, `about:blank` and `data:` URLs only.         |
| `action`     | click, fill, select, drag, hover, press, wait_for                                            | User-emulating actions; bounded by anti-wedge deadlines.                                                                 |
| `human`      | confirmation hooks, await_human, profile_snapshot, profile_restore (also needs `action`)     | Pause-for-human is a safety lever, not a posture broadener. The answer comes only from the `browxai` CDP isolated world. |

## Off-by-default capabilities

Each requires explicit opt-in via `BROWX_CAPABILITIES` (env) or `createBrowxai({ capabilities })` (SDK). A loud warning is emitted on first activation.

| Capability            | Tools                                                                                                                                  | Why off by default                                                                                                                                                                                                                                                                                                                       |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `eval`                | `eval_js`, `poll_eval`; `route`, `route_queue`, `sw_intercept_fetch`, `hars` for document, script, worker requests                     | Arbitrary JS in page context runs outside curated handlers.                                                                                                                                                                                                                                                                              |
| `network-body`        | `network_body`, `caches_get` bodies, `start_har` `embed`/`attach`: full response bodies                                                | Response bodies often contain PII / secrets.                                                                                                                                                                                                                                                                                             |
| `byob-attach`         | attach to user's existing Chrome                                                                                                       | Skips managed-profile isolation; touches user data.                                                                                                                                                                                                                                                                                      |
| `clipboard`           | `shortcut` copy/cut/paste writes the OS clipboard (write-only, never read back)                                                        | Cross-application data egress.                                                                                                                                                                                                                                                                                                           |
| `file-io`             | `upload_file`, downloads to workspace, and every workspace file a tool writes (also as a second capability on `action` / `read` tools) | Filesystem touch via the workspace chokepoint.                                                                                                                                                                                                                                                                                           |
| `secrets`             | `register_secret`, secret materialization at egress                                                                                    | Secret values live in process memory; egress order matters.                                                                                                                                                                                                                                                                              |
| `credentials`         | `get_totp`, `get_credential` (the latter also needs `secrets`)                                                                         | Shells out to an operator-supplied password-manager CLI; returns a TOTP code in plaintext.                                                                                                                                                                                                                                               |
| `extensions`          | install/inspect Chrome extensions from `extensions/` or env-only `BROWX_EXTENSIONS_DIR`                                                | Extension code runs with elevated browser privileges.                                                                                                                                                                                                                                                                                    |
| `stealth`             | anti-fingerprint posture tweaks                                                                                                        | Posture is operator-chosen, never a default.                                                                                                                                                                                                                                                                                             |
| `captcha`             | captcha solver glue                                                                                                                    | Third-party service integration.                                                                                                                                                                                                                                                                                                         |
| `device-emulation`    | `emulate_bluetooth`, `emulate_usb`, `emulate_hid`, `device_requests`                                                                   | Synthetic Web device catalogs: the page believes devices exist that do not.                                                                                                                                                                                                                                                              |
| `diagnostics`         | recorder, `diagnostics_note` (write side). `diagnostics_search`, `diagnostics_report`, `perf_audit` and the rest ride `read`           | Captures session artifacts (workspace-scoped, but artifact-producing).                                                                                                                                                                                                                                                                   |
| `canvas`              | canvas-app eval routing (figma / tldraw / excalidraw plugins)                                                                          | Composes with `eval`; canvas-app plugins gate through this.                                                                                                                                                                                                                                                                              |
| `native-device`       | none (gates the `ios-app` / `android-app` engines at `open_session`)                                                                   | Installs and launches apps and drives OS-level input on a simulator or emulator. | `replay`              | `.browx` session-replay artifact capture (DOM + network + console)                                                                     | Archive carries real page content; as sensitive as the session was.                                                                                                                                                                                                                                                                      |
| `self-approval`       | `approve_actions`                                                                                                                      | Lets the agent answer the confirm hooks meant to stop its own actions.                                                                                                                                                                                                                                                                   |
| `human-gate-override` | none (gates a branch of `set_permission_policy` / `set_fs_picker_policy` / `set_notification_policy` / `open_session`)                 | Lets the agent move a policy off `ask-human` and answer the prompt itself.                                                                                                                                                                                                                                                               |
| `operator-channel`    | none (routes `await_human` and the confirm hooks to the daemon socket)                                                                 | Makes the daemon behind an operator-set socket the only answer path. `self-approval` and `human-gate-override` skip it, so booting with either logs a warning.                                                                                                                                                                           |
| `live-view`           | none (the operator-socket daemon starts a screencast; frames go to that socket only)                                                   | Needs `operator-channel`, or the server will not start. Masking does not cover pixels. The agent cannot start, stop or read it.                                                                                                                                                                                                          |

## Composition rules

- A tool may require **multiple** capabilities. `get_credential` requires `credentials` and `secrets`; `screenshot({path})` adds `file-io` to its `read` gate, and so do `dump_storage_state({path})` and `export_playwright_script({path})`. `pdf_save`, `heap_snapshot`, `perf_start`, `perf_stop`, `start_har`, `artifact_save`, `auth_save` and `open_session` with `har` or `recordVideo` add `file-io` to their `action` gate (`src/tools/file-write-gate.ts`), `profile_snapshot` adds it to its `human` gate, and `perf_audit` and `layout_thrash_trace` add it to their `read` gate for the trace files they write; the deep tools among them check it after the engine gate. `navigate` adds `file-io` for a `file:` URL (workspace-rooted), `eval` for `javascript:` and `extensions` for an extension page; any other non-web scheme needs the env-only `BROWX_NAVIGATE_EXTRA_SCHEMES`, which no config layer can widen (`src/tools/navigation-gate.ts`, `src/policy/navigation-scheme.ts`). `poll_eval` is gated by `eval` alone. `route`, `route_queue` and `sw_intercept_fetch` are `action` tools that answer data and static requests; answering a document, script or worker request, or installing a canned response with an HTML, XHTML, SVG or JavaScript content type, adds `eval` (the rule and the resource-type list live in `src/page/fulfil-policy.ts`). The HARs `open_session({hars})` replays follow the same resource-type rule through a guard route (`src/page/har.ts`). `canvas_query` requires `canvas` + the host adapter's declared capabilities. `open_session` adds `action` for `storageState`, `authState` and `hars`, and `profile_restore` adds `action` to its `human` gate, because each writes cookies and storage or answers requests in a session (`src/tools/open-session-policies.ts`, `src/tools/input-tools.ts`).
- Writes under their own capability: `start_recording({replay})` writes `.browx` under `replay` and the recorder writes diagnostics JSONL under `diagnostics`; neither adds `file-io`. Reading a workspace file (`inject_storage_state` with a path, `open_session` `storageState` / `authState` / `hars`, `auth_load`, `memory_diff`, `perf_insights`, `heap_retainers`) needs no `file-io`.
- Capability composition is multiplicative: missing any required capability returns `capability-denied`.
- The `register` wrapper in `src/tools/host-build.ts` runs the tool's declared capability through the shared gate before the handler, so a handler that calls no gate is still refused. A handler calls `gateCheck` itself only for an argument-conditional second capability. A handler MUST NOT inline its own capability check beyond calling the shared gate.
- The same wrapper runs the attached-session hold (`byob_action`) for tools under the capabilities in `BYOB_HOLD_CAPABILITIES` (`src/tools/byob-hold.ts`).

## Adding a new capability

1. Add the constant to `src/util/capabilities.ts` (default off).
2. Add the threat-model row in `docs/threat-model.md`.
3. Add the row in this file and in the `AGENTS.md` capability table.
4. Add the keystone test asserting the gate blocks when the capability is unset.
5. CHANGELOG entry under `## Unreleased ### Added`.

## Retirement

Deprecating a capability: see [`../release-process/retired-registry-pattern.md`](../release-process/retired-registry-pattern.md). The retired value is accepted with a warning until the next major; never deleted abruptly.
